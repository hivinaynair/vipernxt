# Automatic Jev triage validation

Validated on 1 October 2026. This extends the bounded factory workflow; it does
not raise the prior hosted readiness score or claim universal autonomous recovery.

A blocked engine transition now enters a separate durable triage step before
owner paging. That step claims the checkpoint lease, verifies the full approved
intake hash and derives the actual phase/job/candidate budget and original
station deadline. Typed read failures can continue without a new worker. Other
recoverable recommendations must first establish a concrete action with bounded
read-only Cursor evidence. Investigation exposes only GET, reads at most an
agent and its run, and sends Jev one additional diagnostic classification. It
never trusts worker prose, changes requirements or accepts code.

A verified terminal builder can be replaced within the existing attempt budget;
a reviewer can be replaced within the existing review-format cap. Both preserve
the original stage clock. A lost launch response retains the original agent ID
and reconciles it. Each phase/job/candidate permits at most two additional triage
continuations. Unknown write outcomes without conclusive evidence hold.

Scope removal/change, exhausted budgets, credential/permission failures and
policy/reviewer rejection have deterministic owner guards. Actionable model
routes require a complete valid probability distribution and a unique selected
route with probability at least 0.8. This threshold is a conservative initial
policy, not a calibrated safety or accuracy claim. Missing/weak confidence
investigates once; unresolved or unavailable diagnoses then notify the owner.
The classifier remains advisory (`mode: shadow`, `execution: hold`); only the
fenced coordinator executes verified recovery actions.

## Evidence

- Root suite: **430 pass, 0 fail, 46 files**; this includes **247 Eve tests**.
- Required root type/boundary/token/journey checks pass. The bare kit has no
  product source or engagement requirements packet; those empty checks do not
  establish customer-product acceptance.
- Strict Eve type checking passes. The production-target Vercel build verifies
  Workflow step boundaries and generated invocation limits.
- `test/recovery.test.ts` has **24 fault scenarios** using actual engine, automatic
  continuation and triage code with injected provider responses. Recoverable
  reads reach accepted slice and integrated checkpoints and a draft PR without
  owner notifications. Lost launch reconciliation reaches slice acceptance with
  the same agent identity. Terminal builder replacement consumes its next
  attempt and reaches independent slice acceptance without resetting the clock.
- Owner cases cover expired station/run clocks, exhausted builder/reviewer
  budgets, missing authorization, revoked credentials, policy rejection, uncertain
  writes, weak confidence, model outage, diagnostic identity mismatch and repeated
  recovery. Concurrent pause CAS protection, obsolete workflow fencing, busy
  leases, cache invalidation and pre-launch expiration are also exercised.
- The isolated durable-driver fixture verifies automatic classification after a
  blocked transition, in addition to ownership handoff, hook conflicts and wakes.
- Real workspace Gateway inference after the guard change returned retry_read
  with probability 1 for a temporary read, and repair with probability 0.51 for an
  implementation defect. The latter became investigate rather than authorizing
  resumption. A revoked-credential case returned ask_owner through the deterministic
  guard without invoking the model. These read-only diagnostic inputs were synthetic.

These fault simulations are not a hosted provider-failure pilot. The previous
completed hosted run remains [separately recorded](hosted.md); it had no failure
requiring Jev recovery. Broader live failure injection and empirical confidence
calibration remain necessary before claiming 10/10 or flawless general recovery.
